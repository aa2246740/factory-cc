# Compatibility matrix

Bridge exposes part of Anthropic Messages to Droid and adapts it to Claude Code's native SDK session. Accepting a request field in JSON does not mean that the SDK honors its Messages API semantics.

| Field / behavior | Current adaptation | Validation / limit |
|---|---|---|
| `system` string / text blocks | Host context is appended to user input initially and when changed. The native system prompt stays `claude_code` preset plus stable append. | `tests/unit/system-prompt.test.ts`; client block-level `cache_control` is not forwarded. |
| Live conversation | A persistent streaming-input SDK query receives only new user input; the CLI retains the native transcript. | SDK lifecycle regressions; live GLM three-turn recall and native Read/streamed trace followed by full-history, no-explicit-ID continuation in the same session passed. |
| Session identity | `X-Bridge-Session`, `X-Session-Id`, metadata `session_id` / `sessionId`; otherwise unique complete history-prefix match or pending-tool ownership. | `tests/unit/session-history.test.ts`; `user_id` is not a session ID. Ambiguous continuation returns 409. |
| Session configuration | Model, role-configuration tag, workspace and execution policy must stay compatible with the live session. Host context and the advertised tool catalog may change. | Incompatible execution configuration returns 409; tool/schema changes alone do not change session identity. The role header is not authoritative host workflow instructions. |
| Cold supplied history | Prior messages are imported as reference context; old tool calls are historical text, not replayed actions. Text/images are retained. | No claim of exact native replay, reasoning-state restoration or signed-thinking preservation. |
| `image` / `document` user blocks | Structured content in an ordinary user turn is passed into SDK input. Unsupported user block types return 422. | Backend/model support still applies. The MCP result path has a narrower content mapping: mixed documents are rejected before submission. |
| Tool execution ownership | Only concrete file/shell equivalents from Droid's catalog are covered by native execution: Read/Edit/Write/Create/LS/Grep/Glob/Execute/Bash/MultiEdit/NotebookEdit. All other advertised host/plugin tools use `mcp__droid__*`. Claude Code's preset remains enabled. | Factory `Skill`, `Task`, `ToolSearch`, `ExitSpecMode` and Mission controls retain their host semantics. A matching tool name does not make Factory skills or task IDs native Claude entities. |
| `tools` / `input_schema` updates | Update registrations on the same SDK MCP server, notify `tools/list_changed`, and wait for `mcpServerStatus` to confirm the expected names before releasing the waiting callback. Omitted `tools` retains the catalog; `[]` clears it and blocks native tool execution for that request through the official PreToolUse hook, including bypass mode. Restoring tools later preserves the same native conversation. | Real BYOK hot-add succeeded on the first continuation. Status exposes names, not schema versions: immediate model visibility of a same-name schema replacement is not established. The server validates new inputs against the new schema; unsupported conversion returns 422. |
| Native skills / subagents | Native Claude skills and agents remain separate from Factory's MCP `Skill` and `Task`. Native slash commands retain the last text block when host context is added. | No automatic conversion of Factory skill files or custom droids. BYOK's isolated Claude config does not automatically inherit the user's ordinary `~/.claude/skills`. |
| Host workflow / role | When Factory supplies a nonempty `system`, preserve its role/skill/workflow instructions without header-derived role appendices. `X-Bridge-Role` is a model-configuration/session tag. Only absent host instructions use role fallback, and orchestrator guidance also requires real Mission controls. | Live Factory Task subagents inherited an orchestrator header. Neither that header nor `Task` alone proves the request is an orchestrator. |
| MCP `tool_use` / `tool_result` | Native callback waits across HTTP replies; match by tool ID, preserve supported result content, and reject unknown/cross-session/incomplete/conflicting results. | Real SDK `TaskOutput` round trip passed with a deterministic local result fixture, not a full Mission. A missing callback ID requires a unique pending name/input match; identical parallel calls are rejected as ambiguous. All results from a preceding response must arrive together; partial batches return 409. |
| Mixed tool result and host content | Supplementary text/base64 images and changed host context are labeled as host continuation and attached once to the first fresh MCP result in the batch. The original callback resumes without an extra SDK user turn. | Mixed documents or other unsupported MCP content return 422 before catalog/mailbox/result-fingerprint mutation, leaving pending results available for a corrected request. New context attached only to already-delivered results is rejected. |
| Factory Skill / Mission start | Factory `Skill` returns its full instructions through the real tool callback; Factory `Task`, `ProposeMission` and `StartMissionRun` execute in Droid. | The unseeded GLM BYOK Mission passed with recovery: 3 completed features, 5 passed assertions, original tests preserved and green, no runtime errors or pending work. The initial 20-minute timeout remains recorded separately; official session continuation completed the same Mission. |
| Native tool rejection / handoff | Publish externally only after actual MCP handler entry and join it with the native tool ID using canonical arguments. Schema/permission rejection must not produce a Droid call. | Independent official CLI + GLM BYOK probe passed: native `-32602` rejected invalid arguments, a corrected EndFeatureRun with reordered fields executed the external fixture once, and the same SDK session produced the correct final answer. This does not establish full Mission success. |
| Worker termination | Official authenticated SessionStart/PostToolUse/SessionEnd hooks bind host generations and close the owned native query. | PostToolUse results are used only when actually observed. EndFeatureRun may end the host before PostToolUse; SessionEnd then interrupts its native waiter without inventing a successful result. Terminal or interrupted callbacks cannot resume after restart. |
| Permissions | Default `ask` waits on authenticated `/control` UI or CLI decisions; Droid MCP actions remain host-owned. Explicit `bypass` selects SDK bypass permissions. | Real native Bash deny/allow/cancel probes passed: zero effects on denial/cancel, one execution on approval, stale approval 409. Native CLI policy may allow operations without invoking canUseTool. |
| `stream` | Live text and native-tool traces use SSE; terminal usage is included in `message_delta`. Runtime failures emit SSE `error`, not successful `end_turn` text. | `tests/unit/sse-stream.test.ts`, protocol lifecycle tests. A preliminary input count is not the final usage. |
| Cancellation / timeout | Disconnect, explicit cancel and timeout stop the session; run-droid also forwards OS signals and launch-owned exit/cancel events. | Real native pending-approval cancellation and POSIX wrapper process-tree tests passed. In-app raw-TTY cancellation is governed by Factory hooks; ordinary idle notifications are not treated as cancellation. |
| Idle eviction / resume | Bound live CLI processes, evict idle resumable sessions, and reuse official SDK session IDs. | SDK lifecycle + store tests. Native transcript must exist; pending MCP callbacks after process restart return 409. |
| `max_tokens` | Required and validated as positive; not a hard per-HTTP SDK token cap. `BRIDGE_MAX_TURNS` limits SDK turns separately. | Do not treat it as a billing cap. |
| `tool_choice` | Omitted/auto uses native agent behavior; none enforces the per-request no-tool guard. | Forced any/specific-tool selection and disable_parallel_tool_use return 422 before SDK work because the native agent loop cannot guarantee those API semantics. |
| `temperature`, `top_p`, `top_k`, `stop_sequences` | Parsed but not forwarded as equivalent query settings. | Unsupported semantics; no claim of sampling parity. |
| `thinking` / signed thinking | No complete request/response mapping. Signed history is not fabricated during cold import. | Not validated as Messages-compatible extended thinking. |
| `cache_control` | Client hints are not forwarded. Claude Code controls its provider prompt/cache layout. | GLM cache reads observed with stable system/tools hashes in the recorded run; missing cache-create counters mean partial coverage. Dynamic schema changes can invalidate a cached prefix while retaining the same session. |
| Provider-message `usage` | Merge stream start/deltas and assistant blocks by message ID, then report new usage since the prior reply. Include source, status and coverage. | `tests/unit/usage-ledger.test.ts`; missing data is unknown. Observed message count excludes unexposed helper calls. |
| SDK `result.usage` / `modelUsage` | Main-agent per-turn usage and latest cumulative SDK snapshot are retained separately from provider-message usage. | Cumulative snapshots can include resumed history, subagents and compaction; never sum successive result snapshots. `costUSD` is estimated. |
| Context compaction | Preserve SDK compact status/boundary metadata and native session continuity. | GLM BYOK manual `/compact` and automatic compaction both passed with recall. The automatic test lowered the threshold through documented process-local configuration and observed a real auto boundary; default-threshold behavior remains untested. Empty command text / unknown provider usage does not imply no model work. |
| Token counting | `POST /v1/messages/count_tokens` returns HTTP 501. | No fabricated exact count. |
