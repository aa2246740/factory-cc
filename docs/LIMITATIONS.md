# Limitations

- Recorded online validation used GLM-5.2 BYOK through unmodified Claude Code. [Native evidence](../evidence/native-session-validation-2026-10-15.json) covers chat, cache observations, native tools, continuation and manual `/compact` with recall. [Automatic compaction](../evidence/auto-compaction-validation-2026-10-15.json) also passed with two recall checks using a lowered documented threshold; default-threshold behavior remains untested. [Factory host evidence](../evidence/factory-host-validation-2026-10-15.json) covers hot-add and Skill/Task/Mission probes. The [full Mission](../evidence/mission-validation-2026-10-15.json) is PASS_WITH_RECOVERY: the initial attempt hit the old 20-minute harness limit, and official session continuation completed the same Mission. This does not establish an uninterrupted full run. Real Claude subscription authentication/billing remains unverified.
- An earlier failed Mission exposed premature handoff: native MCP rejected missing EndFeatureRun arguments after the old Bridge had already forwarded the assistant tool event to Droid, causing later callback-association errors. The correction waits for actual handler entry and joins canonical arguments with the native call ID. An independent official CLI + GLM BYOK probe passed the invalid-call/corrected-retry path. Full Mission acceptance additionally checks runtime errors and pending work; Factory completion alone cannot hide SDK failures.
- Lifecycle hooks must be installed for authentic host completion. SessionStart binds a generation through the official Factory environment file; PostToolUse observes actual results and SessionEnd ends the native session. Normal idle notifications do not mean cancellation. Use the launch-scoped run-droid wrapper to propagate process signals and abnormal exits; a forcibly killed direct Droid process cannot guarantee a final hook. A bridge crash still cannot recreate in-memory callbacks.
- Historical MiniMax Mission PASS and cache figures in `REPORT.md` / `evidence/` describe an older implementation. That version synthesized Mission starts, copied ledger artifacts and mixed usage scopes. Its results are not current Mission acceptance or a reliable precise cache-hit ratio.
- The official SDK/CLI integration pattern is not a guarantee of official support, authorization, or account outcomes. A provider field named `firstParty` in SDK diagnostics does not make a third-party BYOK model an Anthropic model. `BRIDGE_AUTH=subscription` preserves the host's existing environment; it does not authenticate the user or override an existing custom endpoint.
- Public `FACTORY_AIRGAP_ENABLED=1` operation is an observed CLI behavior. It is not a declaration that the public CLI has an official enterprise airgap entitlement. Zero telemetry has not been established.
- `ask` is the default. Native permission callbacks wait on the authenticated `/control` page or control CLI. Decisions apply once to a live callback; cancellation, expiry and shutdown deny outstanding requests. Native rules may allow operations without invoking the callback. Explicit `bypass` is not a filesystem sandbox.
- Bridge defaults to loopback, but `BRIDGE_HOST` is configurable. The bridge client token and Claude Code process permissions govern access; using a separate settings file or `BRIDGE_SDK_CWD` does not create an OS isolation boundary.
- Session continuation requires an explicit session ID, pending-tool ownership, or a unique complete history prefix. Repeated prompt text or metadata `user_id` is insufficient. Changing model, role, workspace or execution policy in an existing session returns 409. Tool/schema changes are applied to the existing MCP catalog and do not change session identity.
- Catalog updates keep the SDK server instance, send `tools/list_changed`, and wait for `mcpServerStatus` to confirm the expected tool names before resuming a callback. Real BYOK hot-add then succeeded on the first continuation; without this barrier, the observed refresh lagged by one turn. Status does not report schema versions, so it cannot establish immediate model visibility of a same-name schema update. The MCP server enforces the new schema, and unsupported conversions are rejected. Catalog changes can alter the tool prefix and cause a cache miss.
- Idle CLI processes are bounded and can resume from a persisted official session ID. Recovery needs the corresponding Claude transcript/config to remain available. In-memory MCP callbacks cannot be recreated after process restart: pending tool continuations return 409. Cold imports reconstruct reference context and do not restore exact native internal state.
- An explicit tools:[] or tool_choice:none forbids all native tools for that request, enforced by official PreToolUse even in bypass mode. This protects Factory title/helper requests without replacing the native tool preset.
- An SDK MCP callback without a tool-call ID must uniquely match a pending call by name/input. Parallel identical calls with identical parameters cannot be safely matched in that situation and return 409 instead of guessing. A continuation must supply all tool results from the preceding response together; partial batches return 409. The successful live `TaskOutput` fixture does not validate these ambiguous parallel cases or a complete Mission.
- Only concrete Droid file/shell equivalents are handled natively. Factory `Skill`, `Task`, `ToolSearch`, `ExitSpecMode`, Mission controls and other advertised plugin tools are forwarded through `mcp__droid__*` for Droid to execute under its own policy. Native Claude skills/agents remain separate; no automatic translation of Factory definitions is implemented. BYOK config isolation also means ordinary user-level Claude skills are not automatically inherited.
- Mixed `tool_result` plus text/base64-image requests attach labeled host continuation to the first fresh real tool result, not a separate user turn. Documents and other unsupported MCP content return 422 before submission and do not consume pending results. All prior-response tool results must still arrive together, and already-delivered results cannot accept new context.
- Factory's nonempty `system` owns roles, skills and workflow instructions; Bridge adds no header-derived role template in that case. Task subagents have been observed inheriting an orchestrator model header, so `X-Bridge-Role` is only a configuration/session tag. Role fallback is used only without host instructions; orchestrator guidance additionally requires real Mission controls. Production SDK mode does not synthesize `StartMissionRun` or copy bookkeeping from leftover directories. Use the explicitly selected mission directory and its validation contract. Tiny Tasks remains a reference fixture.
- Provider-message usage covers messages observable through SDK events. It may omit auxiliary calls such as the manual-compaction summary. SDK cumulative `modelUsage` has a wider, separate scope. Unknown usage is not free usage; SDK `costUSD` is an estimate, not a provider invoice.
- GLM's recorded responses omitted `cache_creation_input_tokens`. The corresponding cache coverage is partial and an exact total hit ratio is unknown. Stable system/tools hashes and nonzero cache-read counters establish the observed runs only, not a future hit-rate guarantee.
- Token counting returns HTTP 501. `max_tokens` is not a strict SDK output/billing cap. Forced `tool_choice` and disabled parallel tools return 422; none is enforced. Sampling parameters, `stop_sequences`, signed thinking, and client `cache_control` do not have full Messages-equivalent mappings; see [Compatibility](COMPATIBILITY.md).
- First-party Droid web/mobile/desktop surfaces and GUI validation are outside the current test scope. Neither Droid nor Claude binaries or authentication checks are patched.

- The default per-request deadline is 10 minutes, and a parked external tool (including StartMissionRun) has an 8-hour deadline. These are absolute configured limits, not rolling activity timers; use BRIDGE_REQUEST_TIMEOUT_MS / BRIDGE_TOOL_WAIT_MS for longer work. Lifecycle hooks release completed workers promptly instead of waiting for those deadlines.
