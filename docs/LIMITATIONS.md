# Limitations

- Factory model-call coverage is scoped, not exhaustive. See the [current surface report](FACTORY-SURFACES.md) for newly verified Spec/custom Droid/review/Factory compaction paths and actual failures/fixes. Auto routing, risk/Shield/Local Signals and image backends have independent provider/organization requirements; fixed custom BYOK does not enable them. Hidden/server-side call-site counts remain unknown. The older static inventory is not an all-path certification.

- Recorded online validation used GLM-5.2 BYOK through unmodified Claude Code. [Native evidence](../evidence/native-session-validation-2026-10-15.json) covers chat, cache observations, native tools, continuation and manual `/compact` with recall. [Automatic compaction](../evidence/auto-compaction-validation-2026-10-15.json) also passed with two recall checks using a lowered documented threshold; default-threshold behavior remains untested. [Factory host evidence](../evidence/factory-host-validation-2026-10-15.json) covers hot-add and Skill/Task/Mission probes. The historical [2026-10-15 Mission](../evidence/mission-validation-2026-10-15.json) is PASS_WITH_RECOVERY: the initial attempt hit the old 20-minute harness limit, and official session continuation completed the same Mission. That historical run was not uninterrupted. The fresh [2026-10-16 Mission](../evidence/mission-final-validation-2026-10-16-r3.json) passed continuously in 1126s; its exact source fingerprint precedes three separately verified final changes described in the [final summary](../evidence/final-validation-2026-10-16.json). Real Claude subscription authentication/billing remains unverified.
- An earlier failed Mission exposed premature handoff: native MCP rejected missing EndFeatureRun arguments after the old Bridge had already forwarded the assistant tool event to Droid, causing later callback-association errors. The correction waits for actual handler entry and joins canonical arguments with the native call ID. An independent official CLI + GLM BYOK probe passed the invalid-call/corrected-retry path. Full Mission acceptance additionally checks runtime errors and pending work; Factory completion alone cannot hide SDK failures.
- Lifecycle hooks must be installed for authentic host completion. SessionStart binds a generation through the official Factory environment file; PostToolUse observes actual results and SessionEnd ends the native session. Normal idle notifications do not mean cancellation. Use the launch-scoped run-droid wrapper to propagate process signals and abnormal exits; a forcibly killed direct Droid process cannot guarantee a final hook. A bridge crash still cannot recreate in-memory callbacks.
- Historical MiniMax Mission PASS and cache figures in `REPORT.md` / `evidence/` describe an older implementation. That version synthesized Mission starts, copied ledger artifacts and mixed usage scopes. Its results are not current Mission acceptance or a reliable precise cache-hit ratio.
- The official SDK/CLI integration pattern is not a guarantee of official support, authorization, or account outcomes. A provider field named `firstParty` in SDK diagnostics does not make a third-party BYOK model an Anthropic model. `subscription`, `anthropic-api` and `cloud` refuse conflicting environment variables, but their account classification is not live-verified. Run `npm run doctor -- --auth subscription` first; that check sends no prompt. An unrecognized `accountInfo` fails closed.
- Public `FACTORY_AIRGAP_ENABLED=1` operation is an observed CLI behavior. It is not a declaration that the public CLI has an official enterprise airgap entitlement. Zero telemetry has not been established.
- `ask` is the default. Native permission callbacks wait on the authenticated `/control` page or control CLI. Decisions apply once to a live callback; cancellation, expiry and shutdown deny outstanding requests. Native rules may allow operations without invoking the callback. Explicit `bypass` is not a filesystem sandbox.
- Bridge defaults to loopback, but `BRIDGE_HOST` is configurable. The bridge client token and Claude Code process permissions govern access; using a separate settings file or `BRIDGE_SDK_CWD` does not create an OS isolation boundary.
- Session continuation requires an explicit session ID, pending-tool ownership, a unique complete history prefix, or an exact retained user/assistant turn in an authenticated idle Factory session after compaction. Repeated prompt text or metadata `user_id` is insufficient. An explicit model catalog allows idle model changes by closing and resuming the same persisted native session; pending tools, approvals, background tasks or missing persistence reject the change. Cross-model cache reuse is not guaranteed. Role, workspace and execution-policy changes still return 409. Tool/schema changes do not change session identity.
- Catalog updates use deterministic versioned names for changed schemas/descriptions, so the public SDK name barrier confirms the exact revision. Stable definitions and idle-resume retain names. Ajv validates the full advertised JSON Schema without transforming caller parameters. Root `__proto__` cannot pass the official MCP parser unchanged and is explicitly rejected; a schema change may still cause a legitimate cache miss.
- Idle CLI processes are bounded and can resume from a persisted official session ID. Recovery needs the corresponding Claude transcript/config to remain available. In-memory MCP callbacks cannot be recreated after process restart: pending tool continuations return 409. Cold imports reconstruct reference context and do not restore exact native internal state.
- Native tools require current advertised Factory equivalents, checked by official PreToolUse even in bypass mode. Omitted/empty tools or tool_choice:none grants no tool authority. Factory Skill/Task do not implicitly grant Claude-native Skill/Agent. Spec mode is locked read-only through authenticated hooks until the exact successful ExitSpecMode receipt. Factory classifiers are not run by native Bash; explicit bridge bypass is a separate permission choice, not a claim of Factory auto-low equivalence.
- An SDK MCP callback without a tool-call ID must uniquely match a pending call by name/input. Parallel identical calls with identical parameters cannot be safely matched in that situation and return 409 instead of guessing. A continuation must supply all tool results from the preceding response together; partial batches return 409. The successful live `TaskOutput` fixture does not validate these ambiguous parallel cases or a complete Mission.
- Only concrete Droid file/shell equivalents are handled natively. Factory `Skill`, `Task`, `ToolSearch`, `ExitSpecMode`, Mission controls and other advertised plugin tools are forwarded through `mcp__droid__*` for Droid to execute under its own policy. Native Claude skills/agents remain separate; no automatic translation of Factory definitions is implemented. BYOK config isolation also means ordinary user-level Claude skills are not automatically inherited.
- Mixed `tool_result` plus text/base64-image requests attach labeled host continuation to the first fresh real tool result, not a separate user turn. Documents and other unsupported MCP content return 422 before submission and do not consume pending results. All prior-response tool results must still arrive together, and already-delivered results cannot accept new context.
- Factory's nonempty `system` owns roles, skills and workflow instructions; Bridge adds no header-derived role template in that case. Task subagents have been observed inheriting an orchestrator model header, so `X-Bridge-Role` is only a configuration/session tag. Role fallback is used only without host instructions; orchestrator guidance additionally requires real Mission controls. Production SDK mode does not synthesize `StartMissionRun` or copy bookkeeping from leftover directories. Use the explicitly selected mission directory and its validation contract. Tiny Tasks remains a reference fixture.
- Provider-message usage covers messages observable through SDK events. It may omit auxiliary calls such as the manual-compaction summary. SDK cumulative `modelUsage` has a wider, separate scope. Unknown usage is not free usage; SDK `costUSD` is an estimate, not a provider invoice.
- GLM's recorded responses omitted `cache_creation_input_tokens`. The corresponding cache coverage is partial and an exact total hit ratio is unknown. Stable system/tools hashes and nonzero cache-read counters establish the observed runs only, not a future hit-rate guarantee.
- Token counting returns HTTP 501. `max_tokens` is not a strict SDK output/billing cap. Forced `tool_choice` and disabled parallel tools return 422; none is enforced. Sampling parameters, `stop_sequences`, signed thinking, and client `cache_control` do not have full Messages-equivalent mappings; see [Compatibility](COMPATIBILITY.md).
- Droid web/mobile/desktop surfaces remain outside this CLI/PTY/JSON-RPC scope. Neither Droid nor Claude binaries or authentication checks are patched.

- BRIDGE_REQUEST_TIMEOUT_MS (10 minutes) is an idle limit: any SDK message, text delta or tool event restarts it, and pending approvals pause it (they have BRIDGE_APPROVAL_TIMEOUT_MS, 30 minutes). A native tool that runs that long without output counts as idle. BRIDGE_TURN_MAX_MS (2 hours) caps a turn regardless of progress. On timeout the turn is interrupted; if it winds down within 5 seconds the session stays resumable, otherwise it fails. A session parked on an external tool (including StartMissionRun) expires after 30 idle minutes (BRIDGE_TOOL_WAIT_TIMEOUT_MS, capped by BRIDGE_TOOL_WAIT_MS at 8 hours). An expired session is marked interrupted, frees its slot and never replays the tool; raise BRIDGE_TOOL_WAIT_TIMEOUT_MS for Mission tools that legitimately return later. Lifecycle hooks release completed workers promptly instead of waiting for those deadlines.

- BYOK requires an explicit endpoint/model/key-variable triple in production and probes. Missing configuration or a vanished key fails closed without trying ambient keys or subscription auth. BYOK, subscription, anthropic-api and cloud child processes receive a base allowlist (proxies, CA paths, locale) rather than the full parent environment. `BRIDGE_ENV_PASSTHROUGH` can add names; a forbidden name throws. `inherit` is the only mode that copies the shell. Subscription no longer preserves API keys or cloud routers.
- Factory hosted `/droids` generation rejected unauthenticated airgap in a real PTY test. The local `/relay-droid` command uses the authorized Bridge and writes a validated project definition. Its installer also registers a Factory skill for natural-language discovery after restart. Skill selection depends on the model; the explicit command remains available. Neither path modifies or intercepts the closed hosted menu.
- Actual model choices are configured explicitly, not inferred from account entitlements. Claude aliases resolve through the installed CLI; a provider must support each selected model. The native Bash generator follows its session's selection, while Factory's explicit `/relay-droid` shell command inherits the launch-default `BRIDGE_MODEL_ID` and does not follow later `/model` changes.
